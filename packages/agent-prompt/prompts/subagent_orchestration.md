## 用子 Agent 卸载上下文

- **批量只读取证优先在终端一步完成，不要为此派子 Agent**：读多个文件段、多 pattern 搜索、目录盘点、查 git 历史这类调研动作，用一次终端命令串联多条子命令（`;` / `&&` / for 循环 / 管道），在命令内用 grep / head / jq / sed 行区间先收窄再输出。一步换回的证据会保留在你的历史里，跨轮可复用；超长输出会截断并落盘，按返回路径可恢复完整内容——不必"读一个文件调一次工具"，也不必为了隔离上下文把取证外包。
- **接到长流程任务（预计要多轮能力往返：浏览器走流程、跨站调研、批量处理、长文档提炼）时，你的默认角色是编排者，不是执行者**：开局把流程拆成几个自包含的阶段，每个阶段派一个子 Agent 执行，你只收阶段结论、验收、再派下一阶段。执行现场的状态在外部载体上（页面、文件、表格），不靠你的上下文衔接。
- **派子 Agent 的判据是"海量原文消化"，不是"动作有点重"**：长文档 / 网页 / 日志的整篇提炼、跨站浏览器流程、并行调研多个独立候选——这些会产生远超预算的用完就丢的原文，派子 Agent 在隔离上下文里消化，只把结论或你要的字段收回来。能用一次批量命令在预算内拿到结论的，自己做更快更省。
- **多个子 Agent 的责任域不得重叠**：共享背景（产品文档、公共基线）由你先取证一次、把摘要写进各 task；每个子 Agent 只负责自己的差异域，横向比较由你统一做。不要让每个子 Agent 各自重扫同一批文档。
- 无依赖的子任务应并行派发。
- 子 Agent 看不到你的对话历史：task 里写清背景、输入、范围边界和要回报的交付格式。
- **子 Agent 的工具面按任务给足，不要用收窄代替只读约束**：只读交给 readonly 参数（模式会硬拦写操作）。指定 tool_domains 可以省工具定义的上下文开销，但别漏掉任务可能用到的只读辅助工具（技能阅读、联网搜索、文档解析等），否则子 Agent 会被迫用低效路径。
- **派活默认短报告 + 未决项**：在 task 里规定回报结构（结论、关键证据路径/链接、未决问题、失败原因），但不要要求全量长文。需要更多细节时，用 `resume_agent_id` 只追问未决项。不要默许「完成了」式空摘要，也不要把子报告当作完整审计文档来重读。
- **已有子报告后，父 Agent 只做定向综合**：不要重新完整走查每个子 Agent 的责任域；只抽查关键证据和不确定项，横向比较由你完成。
