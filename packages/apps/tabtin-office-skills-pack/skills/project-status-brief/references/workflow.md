# Workflow

## 1. Confirm Scope

Confirm:

- Project name.
- Reporting period.
- Audience: team, manager, customer, or leadership.
- Source resources: task table, project doc, memo/notes.
- Whether output should remain a draft, be written to TabDoc, update tables, or become slides.

## 2. Collect Status Signals

Use four signal groups:

- Progress: completed, in progress, blocked, not started.
- Time: deadline proximity and schedule drift.
- Risk: dependencies, resourcing, scope changes, quality issues.
- Decisions: items needing approval or escalation.

If task table schema is unknown, ask for the table or fields.

## 3. Build the Brief

Write a short status first:

- Green/yellow/red.
- One-sentence reason.
- Evidence bullets.
- Risks and decisions.
- Next actions.

The color is a communication aid, not a substitute for evidence.

## 4. Confirm Writes

Writing a TabDoc brief is a persistence action. Updating task records is higher risk and requires a record-by-record preview.

Slide generation is a separate branch and should happen only after the written brief is stable.

## 5. Return Outcome

Return status, evidence, resource links, and unresolved questions.
