# Workflow

## 1. Define the Report

Confirm:

- Period: week, month, sprint, quarter, or custom dates.
- Audience: self, manager, team, customer, or leadership.
- Scope: project, team, personal work, or a business function.
- Output: draft only, TabDoc report, or report plus slide handoff.

## 2. Collect Facts

Prefer user-provided material first. Then use available TabTin resources:

- Memo or notes for raw activity.
- TabDoc for project context and decisions.
- TabData for task, metric, customer, or issue records.

Record source counts and obvious gaps. If the table name or fields are unknown, ask the user instead of guessing.

## 3. Build the Report

Separate:

- Completed work.
- Meaningful progress.
- Risks and blockers.
- Next period plan.
- Support or decisions needed.

Do not turn plans into completed work. Do not inflate impact when the source only says work started.

## 4. Persist or Hand Off

Show the draft before writing to TabDoc. If the user wants slides, first finish the report logic, then hand off to the TabSlide path described in `tooling.md`.

## 5. Close the Loop

Return the report link or draft, source coverage, missing inputs, and any recommended follow-up.
