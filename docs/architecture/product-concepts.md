# TabTin 产品概念

[English](product-concepts.en.md)

本文定义当前公共产品模型，不记录历史方案。

## 产品理念

TabTin 希望降低人和 Agent 共同工作的协作成本，让个人完成的工作能够被团队接续、复用和检查。

这种协作建立在五个原则上：过程可见、权限可控、结果可检查、工作可交接、责任有人承担。团队因此能够理解工作怎样完成，并基于证据建立信任。

## 关系

```text
Organization
├── Workspace：成员的私有执行现场
├── Agent：AI 参与身份
├── App：工作应用与能力
└── Device：实际执行环境
```

## 核心概念

| 概念 | 定义 | 关键边界 |
| --- | --- | --- |
| Organization | 组织与租户边界，拥有成员、资源和配置 | 不同 Organization 默认隔离 |
| Workspace | 成员的私有执行现场，包含一个工作根、文件、终端、Skill 和 Checkpoint | 每个 Workspace 只有一个执行根 |
| Agent | 拥有角色、规则、模型、Skill、记忆和执行偏好的 AI 身份 | Agent 表示“谁参与”，不表示“在哪里执行” |
| App | 文档、表格、终端、浏览器、消息和集成等一等工作应用 | 人和 Agent 操作同一份 App 结果 |
| Device | 提供终端、文件、浏览器或设备控制的实际运行环境 | 必须遵守 Organization、成员和 Workspace 权限 |

## 工作交接

TabTin 当前提供两种互补的工作交接方式：

- **任务续接**：发送方把 Agent 任务转交给同一 Organization 的成员。系统冻结可共享的必要会话上下文，并记录任务中引用的文档、表格、云端文件和本地文件；接收人选择自己的 Agent 和 Workspace 后，创建独立的续接任务。材料是否可用仍受原资源权限约束。
- **交接包**：在团队会话中发送工作目标、当前进展、下一步和风险，并可引用 Agent 会话、相关消息、文档和表格。接收人可以查看、确认或接手。

两种方式都不会共享发送方的整个本地目录；双方本地环境保持独立，交接材料继续遵守 Organization 与资源权限。

## 明确非目标

- TabTin 不是共享所有成员本地目录的远程文件系统。
- Agent 不会自动获得全部权限。
- 交接不会绕过已有资源权限。
- 代码中的过渡名称不会自动成为公共产品概念。
