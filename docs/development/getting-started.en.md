# Local development and debug builds

[中文](getting-started.md)

This guide runs TabTin from source. Unless noted otherwise, run commands from the repository root.

## Two startup routes

| Route | Use it when |
| --- | --- |
| Agent startup | Let the Agent install the environment, then choose Quick Preview or Full Preview |
| Manual startup | Prepare the environment yourself and run the required low-level command or service |

Quick Preview and Full Preview are the two modes under Agent startup, not additional startup routes. Quick Preview is for opening the desktop client quickly. Full Preview is for complete cross-application local development. Neither is a Community distribution package or a production release build.

## Route 1: Agent startup

Give the [Community development Agent prompt](community-dev-agent-prompt.en.md) and this guide to your Agent. Before either preview, the Agent must inspect the OS, CPU architecture, Node.js, pnpm, Python, Go, Git, Docker, and platform build tools. Missing dependencies may be installed only through the system package manager or an official vendor channel. Unknown installers, third-party scripts, and unverified mirrors are not allowed.

| Result | Agent action | Pause only when |
| --- | --- | --- |
| Installed | Check version, architecture, and PATH, then continue | The version is outside the project requirement |
| Missing but installable | Install through the system package manager or official installer, then recheck | Installation fails |
| Requires administrator rights | Attempt the elevated command | The OS rejects authorization |
| macOS security, Docker first launch, or license confirmation | State exactly what app, permission, or button needs confirmation | The user confirms |
| Docker is installed but stopped | Start Docker Desktop or Docker Engine automatically | The OS blocks or rejects startup |
| Docker daemon is not ready | Repeat `docker info` in a bounded loop | The wait limit is reached |

The Agent must not overwrite local configuration, change the global npm registry, bypass health checks, or report success without the required readiness signal. It pauses only for system permissions, Docker first launch, security confirmations, or license confirmations that the OS cannot complete automatically.

After the environment is ready, ask the Agent to run one of these prompts:

```text
Run the “Quick Preview” for https://github.com/tabtin-ai/TabTin.
```

Quick Preview starts the backend and Electron desktop client for a fast desktop experience. It does not start AdminDash or tabtin-web.

```text
Run the “Full Preview” for https://github.com/tabtin-ai/TabTin.
```

Full Preview starts the backend, AdminDash, tabtin-web, and Electron desktop client, and provides the acceptance entry points for desktop, Android, and iOS debug packages. Android and iOS packages are built separately on their target platforms; the Full Preview command does not start them automatically.

### Default server address for Full Preview

When the user does not explicitly provide a server IP, the Agent must detect an active LAN IPv4 address on the computer running the TabTin server and use it as the default server address for all three packaged clients. It must not put `localhost` or `127.0.0.1` into a package that other devices need to access. An explicitly provided server IP always takes precedence.

Use the same `<LAN_IP>` for desktop, Android, and iOS:

- **Desktop:** in the repository-root `.env.local`, set `TABTIN_API_BASE_URL` / `VITE_API_BASE_URL` to `http://<LAN_IP>:6060/api`, and set `VITE_COLLAB_WS_BASE`, `VITE_CENTRIFUGO_WS_URL`, and `VITE_PUBLIC_WEB_BASE_URL` to `ws://<LAN_IP>:4100`, `ws://<LAN_IP>:8100/connection/websocket`, and `http://<LAN_IP>:5176` respectively before Full Preview or a desktop debug build.
- **Android:** build the debug APK with `-PDEV_HOST=<LAN_IP> -PDEV_PORT=6060 -PDEV_WEB_BASE_URL=http://<LAN_IP>:5176`. A physical device must be on the same LAN as the server computer; use the Android Emulator host mapping `10.0.2.2` only when the emulator is intentionally not using a LAN address.
- **iOS:** import the LAN addresses through the environment QR code generated by the desktop client before building or installing the debug package; do not enter `localhost`.

The Agent must also confirm that the server is listening on an address reachable from the LAN and that the OS firewall allows LAN access to ports `6060`, `4100`, `8100`, and `5176`. The final report must record the actual `<LAN_IP>`. If no usable LAN IPv4 can be detected or the ports are unreachable from the device, pause and report the reason; do not silently fall back to a loopback address or an online service.

## Route 2: Manual startup

Manual startup does not require the “Quick Preview” or “Full Preview” prompts. After preparing the environment and configuration below, run the low-level command you need; use `pnpm dev` when you need the complete local integration chain.

### 1. Prepare dependencies

Read `engines.node` and `packageManager` from the root `package.json`; do not guess versions. The current project requires Node.js `>=18.0.0` and declares pnpm `9.15.0`:

```bash
node --version
corepack enable
corepack prepare pnpm@9.15.0 --activate
pnpm --version
```

Python, Go, Git, Docker, and the platform's Electron build tools are also required. Use Homebrew and Apple channels on macOS, `winget` and vendor channels on Windows, and the distribution's official package manager on Linux. Windows packaging requires Visual Studio Build Tools with **Desktop development with C++**. Install Docker only through [Docker's official channel](https://docs.docker.com/get-docker/).

After installing Docker, verify that the daemon is ready:

```bash
docker info
```

### 2. Create local configuration

Copy only a missing file; never overwrite an existing local configuration:

```bash
test -f .env || cp .env.example .env
```

`.env` contains the local base configuration. Put personal overrides in the root `.env.local`. Neither file should be committed. Configure database, Redis, LLM, Sentry, SMS, IM, and payment settings as needed; unconfigured third-party capabilities remain disabled or fail closed and do not silently fall back to an online environment.

Before the first startup, run:

```bash
node scripts/dev.mjs community --doctor
pnpm install --frozen-lockfile
```

### 3. Start the desktop development chain

```bash
node scripts/dev.mjs community
```

This checks and prepares the Community development environment, starts or reuses the local backend, waits for Django, Collab, and Centrifugo to become healthy, and then starts Electron. Success requires the Electron-ready signal and an open desktop window; a process or occupied port alone is not enough. Keep the long-running process in the foreground and stop it with `Ctrl+C`.

For mainland China networks, select the download source explicitly:

```bash
node scripts/dev.mjs community --region cn
```

### 4. Start the complete integration chain

```bash
pnpm dev
```

The complete integration chain runs in this order:

1. Start the local backend and its dependencies, then wait for Django/API, Collab, and Centrifugo health checks;
2. Perform one Electron local build using the local configuration;
3. Start AdminDash;
4. Start tabtin-web;
5. Start Electron.

The command owns all child processes; press `Ctrl+C` to stop them. A failed health check, Electron build, or client startup must stop the flow and report the first error. The personal root `.env.local` is used by both local startup and the Electron build performed by Full Preview.

To debug one service separately, use:

```bash
node scripts/dev.mjs backend
node scripts/dev.mjs admindash
node scripts/dev.mjs tabtin-web
node scripts/dev.mjs electron
```

These individual entries do not replace Full Preview's complete health gates or startup order.

## Community desktop package

A Community package needs four public service URLs and must not contain credentials:

```bash
export TABTIN_COMMUNITY_API_BASE_URL=https://api.example.org/api
export TABTIN_COMMUNITY_COLLAB_WS_BASE=wss://api.example.org/collab
export TABTIN_COMMUNITY_CENTRIFUGO_WS_URL=wss://api.example.org/connection/websocket
export TABTIN_COMMUNITY_PUBLIC_WEB_BASE_URL=https://web.example.org
```

On macOS/Linux run `pnpm --dir apps/tabtin-electron build:mac:community` or `build:linux:community`; in Windows PowerShell set the same `$env:` variables and run `build:win:community`. The installer must appear in `apps/tabtin-electron/dist-app/`. This is the Community distribution flow; it does not satisfy the debug-build acceptance criteria below.

## Acceptance for debug builds

Report success only after the actual debug artifact exists. A running development process, a default release build, or only a `win-unpacked` directory is not sufficient.

- **macOS/Linux Electron:** run `pnpm --dir apps/tabtin-electron build:mac:local` or `build:linux:local` and verify the corresponding artifact in `dist-app/`.
- **Android:** from `apps/tabtin-android`, run `./gradlew :app:assembleDebug` (Windows: `./gradlew.bat :app:assembleDebug`) and verify an APK under `app/build/outputs/apk/debug/`.
- **macOS iOS Simulator:** with Xcode installed, run `xcodebuild` with the Debug configuration and verify `dist/ios-debug/Build/Products/Debug-iphonesimulator/Tabtin.app`.
- **Windows/Linux iOS:** skip and report that macOS and Xcode are required; this is a platform limitation.

On timeout or failure, report the exact error, completed steps, and artifacts actually produced. Do not substitute a release artifact for a debug artifact.
