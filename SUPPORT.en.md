# TabTin Support

[中文](SUPPORT.md)

Choose the channel that matches the nature of your request. This helps maintainers understand and route it efficiently.

## Support matrix

| Need | Channel | Notes |
| --- | --- | --- |
| Reproducible product or code defect | Bug Issue template | Include version, operating system, reproduction steps, expected result, and actual result |
| Well-shaped feature request | Feature request Issue template | Describe the user scenario and current obstacle before proposing an outcome |
| Usage help, open ideas, and experience sharing | Discussions | A complete solution is not required |
| Documentation error | Issue or small documentation PR | Identify the page, incorrect content, and suggested correction |
| Security vulnerability | GitHub private vulnerability reporting | Do not open a public Issue; see [SECURITY.en.md](SECURITY.en.md) |
| Community conduct concern | Private security reporting entry | Prefix the title with “Code of Conduct”; see [CODE_OF_CONDUCT.en.md](CODE_OF_CONDUCT.en.md) |
| Report that cannot be submitted through GitHub | [issue@larchiveai.com](mailto:issue@larchiveai.com) | Prefix security reports with `[SECURITY]`; for other reports include the version, environment, and reproduction steps |
| Deployment assessment, migration, or custom services | [contact@larchiveai.com](mailto:contact@larchiveai.com) | Do not send secrets, tokens, or business data by email |

## Before opening a report

1. Search existing Issues and Discussions to avoid duplicates.
2. Confirm that the problem occurs on the latest public stable version. Older versions are generally not fixed separately.
3. Remove secrets, tokens, conversations, business data, personal information, and local paths from logs, screenshots, and diagnostic files.
4. Provide the smallest useful reproduction instead of only stating that something does not work.
5. If the problem may affect other users' data or system security, stop public discussion and use private vulnerability reporting.

## Community support boundary

Issues and Discussions are supported by maintainers and the community without a guaranteed response or resolution time. Clear reproduction steps, verification evidence, and impact descriptions make reports much easier to act on.

Components may have different maturity levels during the Public Preview. Maintainers prioritize work based on impact, reproducibility, security risk, and the current roadmap.

## Commercial support

Organizations that need deployment assessment, migration assistance, custom development, or other commercial services should contact [contact@larchiveai.com](mailto:contact@larchiveai.com).

Commercial support is separate from community Issues and does not change the visibility of public reports or anyone's open-source license rights.
